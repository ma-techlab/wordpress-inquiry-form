# 要件定義書：MERVELTA Inquiry Manager

WordPress用の見積依頼・問い合わせ管理プラグイン（最小版）

- 作成日：2026-11-06
- 完成目標：2026-11-20（最小版）
- 種別：個人開発のポートフォリオ作品。顧客への納品物ではない

## 1. 目的

製造業・建設業などの小規模事業者のWordPressサイトで、見積依頼と問い合わせを受け付ける。届いた依頼を取りこぼさず、対応状況を管理できるようにする。

ポートフォリオでの狙い：Web制作会社・開発会社の外部パートナーとして、WordPress・PHP・DBでの機能実装と、安全への配慮を説明できる作品にする。

## 2. 想定する利用者

| 利用者 | 立場 | すること |
|---|---|---|
| 訪問者 | 架空の金属加工会社「（例）株式会社サンプル精工」のサイトを見る人 | 見積依頼・問い合わせを送る |
| 管理者 | 同社の担当者（WordPressの管理者権限を持つ） | 通知を受け取り、一覧で確認し、対応状況を更新し、CSVで書き出す |

## 3. 範囲

### 作るもの

1. 入力フォーム（ショートコードで任意のページに置ける。Elementorのショートコードウィジェットでも使える）
2. 専用テーブルへの保存
3. 管理者へのメール通知
4. 管理画面：一覧、詳細、対応状況の更新、管理メモ
5. CSV出力
6. 最小限の不正送信対策
7. 設定画面：通知先メールアドレス
8. 削除時の後片付け（テーブルと設定を消す）
9. 配布用ZIPを作るスクリプト

### 作らないもの（最小版）

- 訪問者のログイン、マイページ
- ファイル添付
- 外部SaaS（CRM・Slackなど）との連携
- 集計・分析・グラフ
- 訪問者への自動返信メール
- 多言語対応（日本語のみ。ただし文字列は翻訳関数を通す）
- 管理者以外の権限設定
- マルチサイト（シングルサイトのみ対象）

## 4. 動作環境

| 項目 | 条件 |
|---|---|
| WordPress | 6.5以上 |
| PHP | 8.3以上（8.1以前はPHP公式のサポートが終了、8.2は2026-12-31に終了するため） |
| 確認に使うPHPの版 | 2026-10-21の重大な脆弱性の修正を含む版（8.3.36以上、8.4.27以上、8.5.12以上。またはUbuntuなどの配布元がCVE-2026-109618・109619の修正を取り込んだ版。例：WSLのUbuntu 26.04の `8.5.4-0ubuntu1.5`）。LocalWPとWSLの両方で、確認前に版を記録する |
| 開発・確認 | LocalWP（Windows）。サーバー契約はしない |
| メールの確認 | LocalWPのMailpitで受信内容を確認する。実際の配信は確認範囲外 |
| 開発用の検査 | WSL上の `php -l`、PHPCS＋WordPress Coding Standards＋PHPCompatibilityWP（`testVersion 8.3-`） |

## 6. データ項目

テーブル `{$wpdb->prefix}mvim_inquiries`

| 列 | 型の目安 | 入力 | 制約 |
|---|---|---|---|
| id | BIGINT UNSIGNED 自動採番 | - | 主キー |
| inquiry_type | VARCHAR(20) | 必須・選択 | `estimate`（見積依頼）/ `question`（問い合わせ）/ `other`（その他） |
| company_name | VARCHAR(100) | 必須 | 100文字以内 |
| contact_name | VARCHAR(50) | 必須 | 50文字以内 |
| email | VARCHAR(254) | 必須 | `is_email()` で検証 |
| phone | VARCHAR(20) | 任意 | 数字・ハイフン・括弧・＋・空白のみ、20文字以内 |
| message | TEXT | 必須 | 2,000文字以内 |
| status | VARCHAR(20) | - | `new`（未対応）/ `in_progress`（対応中）/ `done`（完了）。初期値 `new` |
| staff_note | TEXT | 管理者のみ | 1,000文字以内 |
| created_at | DATETIME | - | 受付日時（サイトのタイムゾーン） |
| updated_at | DATETIME | - | 最終更新日時 |
| mail_sent | TINYINT(1) | - | 通知メールの送信結果（1：成功、0：失敗） |

- IPアドレスは保存しない（送信回数の制限には、ハッシュ化した値を一時的に使うだけ）
- 個人情報の取扱いへの同意チェックは必須入力とし、保存はしない

## 7. 機能要件

### FR-1 入力フォーム

- `[mvim_inquiry_form]` で表示する
- 項目：種別、会社名、担当者名、メールアドレス、電話番号（任意）、内容、個人情報の取扱いへの同意
- 送信先はフォームのあるページそのものとし、`init`（または `template_redirect`）で受け取って処理する
- 入力エラー時（3秒未満の送信を含む）はリダイレクトせず、同じリクエストの中で、どの項目が誤りかを日本語で表示し、入力済みの値を残す。入力値をtransient等に一時保存しない（個人情報を一時保存しないため）
- 成功時だけ元のページへリダイレクトし（PRG。二重送信を防ぐ）、「受け付けました」と表示する
- 入力欄には `label` を付け、必須項目を明示する（アクセシビリティ）

### FR-2 不正送信対策

- nonceを検証する
- 見えない入力欄（ハニーポット）に値があれば、保存せずに成功と同じ表示にする
- フォーム表示から3秒未満の送信は受け付けず、「もう一度送信してください」と表示する（表示時刻は署名付きの隠し項目で渡し、改ざんを検出する）
- 同じ送信元からの送信は10分間に5回まで（送信元はIPアドレスのハッシュで識別し、transientで数える）
  - 数える対象：nonce・ハニーポット・3秒の確認を通過した送信。入力エラーになった送信は数えない
  - 期間：その送信元の最初の送信から10分間の固定窓（送信のたびに期間を延ばさない）
  - 送信元：`REMOTE_ADDR` だけを使う（`X-Forwarded-For` などは偽装できるため使わない）
- 制限にかかった場合は、時間をおいて送るよう案内する

### FR-3 保存

- `$wpdb->insert()` で書式を指定して保存する
- テーブルはプラグイン有効化時に `dbDelta()` で作る。DBのバージョンをオプションに記録する

### FR-4 メール通知

- 保存に成功したら `wp_mail()` で通知する
- 宛先：設定画面の通知先（未設定ならサイトの管理者メールアドレス）
- 件名：`【見積依頼】株式会社〇〇 様より` のように種別と会社名を含める
- 本文：全項目と、管理画面の詳細ページへのリンク
- Reply-To に訪問者のメールアドレスを入れる。`is_email()` で検証済みの値だけを使い、改行を除く
- 送信に失敗しても保存は取り消さない。列 `mail_sent` に結果を記録し、一覧の「状態」列に「通知失敗」と添えて示す。個人情報をログには書かない
- 件名・ヘッダー（Reply-To）と、本文のうち1行で表す項目（会社名・担当者名・メール・電話）から改行を除き、ヘッダーインジェクションを防ぐ。本文の「内容」は改行を残す（本文はヘッダーではないため）

### FR-5 管理画面：一覧

- 管理メニュー「見積依頼」を追加する
- `WP_List_Table` を使う
- 列：受付日時、種別、会社名、担当者名、状態
- 状態で絞り込み（すべて / 未対応 / 対応中 / 完了）と件数表示
- 受付日時の新しい順。1ページ20件
- 会社名をクリックすると詳細へ

### FR-6 管理画面：詳細と更新

- 全項目を表示する
- 状態と管理メモを更新できる
- 更新は nonce と権限を確認する。完了したら一覧または詳細に戻り、結果を表示する

### FR-7 CSV出力

- 一覧画面のボタンから、今の絞り込み条件のままCSVを書き出す
- 文字コードはUTF-8（BOM付き。Excelで文字化けしないため）
- ファイル名：`inquiries-YYYYMMDD.csv`
- 列：ID、受付日時、種別、会社名、担当者名、メール、電話、内容、状態、管理メモ
- `=` `+` `-` `@` タブ・改行で始まる値は先頭に `'` を付ける（CSVインジェクション対策）

### FR-8 設定画面

- 通知先メールアドレスを1件設定できる（Settings APIを使う）

### FR-9 有効化・無効化・削除

- 有効化：テーブルを作る
- 無効化：データは残す
- 削除（`uninstall.php`）：テーブルとオプションを消す

## 8. セキュリティ要件

| 対象 | 要件 |
|---|---|
| 権限 | 管理画面・更新・CSV出力はすべて `current_user_can( 'manage_options' )` を確認する。nonceだけで守らない |
| nonce | フォーム送信、状態更新、CSV出力のすべてで検証する |
| 入力 | `sanitize_text_field()` / `sanitize_textarea_field()` / `sanitize_email()` と、文字数・選択値の検証 |
| SQL | 値を含む問い合わせは `$wpdb->prepare()`。挿入・更新は `$wpdb->insert()` / `update()` に書式を渡す |
| 出力 | `esc_html()` / `esc_attr()` / `esc_url()` / `esc_textarea()` で出力時にエスケープする |
| 直接アクセス | 各PHPファイルの先頭で `ABSPATH` を確認する |
| 個人情報 | IPアドレスを保存しない。開発・確認には架空のデータ（`example.com`）だけを使う |

## 9. 品質の確認（Gate）

### 自動（WSLで実行）

1. `php -l` で全PHPファイルに文法エラーがない
2. PHPCS（WordPress規約）でエラー0件
   - 警告を消すために規約を一律に除外しない
   - 除外する場合は、行単位で理由をコメントに書く
3. PHPCS（PHPCompatibilityWP、`testVersion 8.3-`）でPHP 8.3との互換性の問題が0件
   - 安定版のPHPCompatibility（9.3.5）はPHP 8.4以降の構文・関数を検出できないため、8.4以降の機能は使わずに書き、コードを読んで確認したことを段階ごとに報告する。本当の確認は、LocalWPのPHPを8.3にして動かすこと（手動の確認表に含める）

### 手動（LocalWPで実行。確認表は `docs/TEST-CHECKLIST.md`）

1. ZIPから導入・有効化でき、テーブルができる
2. 固定ページとElementorのページの両方でフォームが表示される
3. 正しい入力で保存され、Mailpitに通知が届く
4. 必須項目の空欄、メールの形式誤り、文字数超過でエラーが出て、入力が残る
5. ハニーポット、3秒未満、6回目の送信がそれぞれ止まる
6. 一覧の絞り込み、ページ送り、詳細、状態・メモの更新ができる
7. CSVをExcelで開いて文字化けせず、`=1+1` のような値が計算されない
8. 管理者以外（編集者など）では管理画面とCSVのURLを開けない
9. `<script>` を含む入力が、画面・メール・CSVで実行されない
10. 削除するとテーブルとオプションが消える
